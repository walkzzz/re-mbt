## 发现

- **[一般]** §0 总体概览与 §1 表格加总数据不一致。§0 声明"已覆盖 209 / 未覆盖 205 / 覆盖率 50.5%"，但 §1 API 清单总览表 52 个模块逐行加总为"已覆盖 219 / 未覆盖 195"（pub API 总数 414 一致）。已覆盖数差 +10，未覆盖数差 -10。§1 表格每行内部自洽（pub = 已覆盖 + 未覆盖），问题出在 §0 概览数字与 §1 表格加总未对齐，影响报告总体可信度。

- **[一般]** §1 表格加总与 §2 明细表加总不一致。§1 表格未覆盖加总 195，§2 各子节未覆盖加总：§2.1(4)+§2.2(19)+§2.3(12)+§2.4(28)+§2.5(23)+§2.6(18)+§2.7(16)+§2.8(10)+§2.9(64) = 194。差 1 个未覆盖 API，说明 §2.9"其他模块未覆盖 API（汇总）"节漏列了 1 个未覆盖 API（某模块在 §1 表格中未覆盖数不为 0，但在 §2.9 汇总描述中未体现或计数少 1）。

- **[轻微]** §0 关键发现第 1 条称"内部数据结构（Desc/ET/Marks/Mark/Positions/StateHashTable/CompileIdx/CompileState）几乎无直接测试"，但 §1 表格中 Desc 标记已覆盖 1（`Desc::status` 仅间接），而 §0 覆盖层次分布将 Desc 归入"中等覆盖模块"。Desc 实际覆盖率 1/18=5.6%，应归入"0% 覆盖模块"或"极低覆盖"类别，分类描述与实际数据有偏差。

## 修改要求（仅 REJECTED 时）

### 问题 1：§0 与 §1 数据不一致

**问题**：§0 总体概览声明 209 已覆盖/205 未覆盖，§1 表格加总为 219 已覆盖/195 未覆盖，差 10。

**为什么是问题**：覆盖率差距报告的核心价值在于精确的数据基线，§0 概览数字与 §1 明细加总不一致会让后续 T9+ 补测试任务无法确定真实基线（到底是 209 还是 219 已覆盖）。

**期望修正方向**：重新核对 §1 表格各模块的已覆盖/未覆盖数，确认正确值后同步更新 §0 概览的"已覆盖 API 数 / 未覆盖/浅覆盖 API 数 / 总体覆盖率"三个字段。若 §1 表格加总 219/195 是正确的，则 §0 应改为"已覆盖 219 / 未覆盖 195 / 覆盖率 52.9%"；若 §0 的 209/205 是正确的，则需找出 §1 表格中哪 10 个 API 被错误计入已覆盖。

### 问题 2：§1 与 §2 数据不一致

**问题**：§1 表格未覆盖加总 195，§2 明细表加总 194，差 1。

**为什么是问题**：§2 明细表应穷尽列出所有未覆盖 API，漏列 1 个会导致该 API 在后续补测试时被遗漏。

**期望修正方向**：对照 §1 表格中每个未覆盖数 > 0 的模块，检查 §2.9 汇总节是否完整列出该模块的未覆盖 API 数。找出漏列的 1 个 API，补充到 §2.9 或相应子节。
